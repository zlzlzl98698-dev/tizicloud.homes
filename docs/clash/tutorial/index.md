> [!NOTE] Answer-First 核心结论
> **核心痛点快速解答**，在日常使用【Clash 教程】相关功能时，绝大多数用户首选且应当长期保持的运行模式是“Rule 规则分流模式”。该模式下境内应用与网站自动走物理直连通道，境外被阻断服务自动通过加密节点转发，兼顾本土低延迟与跨国访问。若遭遇游戏客户端、终端命令行工具或特定桌面软件不走代理的棘手问题，首选解决方案是安装系统服务模式并开启“TUN 模式”，通过内核级虚拟网卡无差别接管第三层数据包。在服务商底层支撑上，建议优先选用具备多年稳定运营资质且内网专线冗余的成熟品牌（如 [光速云](/brands/guangsu/)），以确保日常使用不发生频繁的节点超时。

## 🎯 玩转 Clash 的三大黄金法则

为了确保代理环境兼顾极致访问速度与日常操作便利，使用者在操作客户端时必须恪守以下三项基本原则。

### 1. 默认坚守 Rule 规则模式，切忌长久停留在 Global 全局

许多新手在遇到特定网页打不开时，习惯一键切换至 Global 全局模式，并就此长期保持。全局模式会强行将包括国内微信、淘宝、网易云音乐以及局域网打印机在内的所有网络通信全部送往境外节点。这不仅会白白损耗昂贵的境外套餐流量，而且会导致国内软件频繁弹出异地登录风控警告。在解决偶发访问问题后，必须立即切回 Rule 规则分流模式。

### 2. 游戏联机与开发环境强推 Service 搭配 TUN 模式

系统自带的系统代理开关仅仅修改了操作系统内部的一个注册表键值，许多底层的网络进程（如 Git 命令行、Python 包管理器、Steam 游戏以及各类跨国竞技联机客户端）在发起网络套接字连接时根本不读取该设置。彻底消除软件不走代理的终极手段是安装系统服务模式（Service Mode），并在界面中开启 TUN 虚拟网卡。虚拟网卡能够直接在网卡驱动层实现全包拦截，省去为每个软件单独配置端口代理的繁琐工作。

### 3. 养成关机或退出前关闭代理的良好习惯

在日常使用中，很多用户经常遭遇“昨天还能上网，今天开机整台电脑连百度都打不开”的断网故障。这绝大多数是因为在没有正常退出客户端的情况下强行关机，或者客户端异常崩溃，导致操作系统底层的系统代理开关未能正常复位还原。若操作系统继续将数据包发往已经关闭的本地代理监听端口，就会引发网络瘫痪。遇到开机断网时，只需重新打开客户端并正常退出，或者在 Windows 网络设置中手动关闭代理服务器开关即可迅速恢复。

### 1. Rule 规则分流与 Global 全局出站的流量路由机理

理解规则模式与全局模式的分歧，关键在于理清网络数据包在进入代理核心后的裁决逻辑。

在 Rule 规则模式下，数据包到达分流引擎后，核心会调出路由表自顶向下逐行比对。例如当你在浏览器中打开国内主流视频站点或电商应用时，其域名与目标 IP 会准确命中预设的 GEOIP 或 DIRECT 直连条目，核心直接调用本地物理网卡将数据发往本土互联网，丝毫不占用任何境外代理流量。只有当访问被墙的海外社交平台或学术数据库时，流量才会匹配到 PROXY 规则并封装发往出海专线。

而在 Global 全局模式下，内部的整个智能分流决策引擎会被强制彻底绕过。无论你的请求目标是国内银行、本地局域网路由器还是海外网站，核心都会不加辨别地将每一个数据包全部塞进当前选定的出站节点隧道中。这不仅导致原本秒开的国内应用因为绕行海外而变得奇慢无比，更会导致国内金融风控系统将你的账户标记为异常异地登录。因此，全局模式仅应作为调试分流规则失效时的临时排障工具。

### 2. System Proxy 环境变量与 TUN 虚拟网卡的深层差异

许多用户困惑为什么勾选了客户端界面上的系统代理开关后，命令行中的 Git 克隆或者大型在线游戏依然无法连接境外网络。

系统代理的本质是在 Windows 注册表或 macOS 系统配置中声明了全局 HTTP 与 SOCKS 代理的环境变量。这个机制是软性的，完全依赖上层应用程序自觉读取并遵守系统代理配置。像 Chrome、Edge 等通用浏览器天生会主动读取该设置，因此可以开箱即用顺畅翻墙。然而，大多数专业开发工具、游戏引擎以及防作弊模块在设计之初就直接调用底层的网络套接字接口，完全不理睬操作系统的代理环境变量。

TUN 虚拟网卡模式则在操作系统内核与物理网卡之间插入了一张虚拟的网络适配器驱动。它通过修改系统默认路由表，将整台电脑的所有 IP 数据报文在网络层第三层强行截获并重定向至代理核心。在 TUN 模式下，无论应用程序是否支持代理设置，哪怕是直接发起裸 UDP 广播的联机游戏，所有网络流量都无法逃逸核心的精准监管，真正实现了操作系统级别的全透明全局接管。

### 1. 客户端图形界面五大核心模块的职责与数据联动

打开 Clash Verge Rev 或同类现代化客户端，左侧通常清晰分布着五个核心功能面板。

- **代理面板**，这是用户日常交互最频繁的板块。它以可视化的卡片形式展示了配置文件中声明的全部策略组与底层节点。用户可以在这里直观查看每个节点的往返延迟，或者在不同的出站国家线路之间一键手动切换。
- **订阅面板**，负责配置文件的全生命周期管理。包括在线订阅的新增、自动更新周期的调整、本地规则的引入以及多服务商配置的自动合并，均在此面板通过图形化界面完成。
- **连接面板**，提供微秒级的系统活动连接追踪。它实时列出当前操作系统中所有处于打开状态的 TCP 与 UDP 会话，精确显示请求发起的源应用程序进程、目标主机名、匹配到的分流规则以及累积传输的字节数，并支持用户针对异常套接字执行强行断开。
- **日志面板**，内核运转的调试监视器。按照不同安全等级（Error、Warning、Info、Debug）输出内核在解析数据包、探测节点存活以及加载规则时的内部执行流水，是排查各种疑难杂症的第一现场。
- **设置面板**，涵盖客户端行为与操作系统集成的总控中心。包括系统代理开关、服务模式安装、TUN 虚拟网卡激活以及启动项管理均在此集中呈现。

### 2. 四大核心策略组调度模型的运行逻辑拆解

策略组（Proxy Groups）是连接分流规则与物理节点的逻辑调度纽带。理解四种不同类型的策略组有助于实现最优的流量分配。

第一种是 **Select 手动选择组**，这是最基础的类型。策略组内部列出若干个可用节点，由用户在界面上明确点选某一个具体节点作为出站通道。在此模式下，流量完全按照用户的意图从固定节点发出，具备绝对的确定性，极其适合对 IP 稳定性要求苛刻的跨境电商店铺管理或者特定跨国办公系统。

第二种是 **URL-Test 自动测速组**，主打性能优先。核心会周期性向指定的测试端点发送握手探针，并自动将所有出站流量绑定到当前往返时延最低的节点上。当首选节点发生拥堵导致延迟劣变时，核心会自动将流量迁移至更新后的低延迟节点，非常适合用于观看高清流媒体视频或下载大型文件。

第三种是 **Fallback 故障转移组**，主打生产高可用。它将多个节点按照预先设定的优先级次序排列。核心在日常状态下始终使用第一优先级的节点出站，即便第二优先级的节点延迟更低也不会发生主动切换。只有当首选节点在设定的心跳周期内连续多次失联超时，核心才会触发容灾转移。该机制有效避免了自动测速带来的节点频繁跳变问题。

第四种是 **Load-Balance 负载均衡组**，适合极高并发场景。内核根据特定的散列算法（如基于目标 IP 的一致性哈希），将多条并发连接均匀分摊到节点池内的多台服务器上，从而成倍扩展整机的总带宽吞吐。

### 3. Service Mode 服务模式与系统底层特权网桥

在现代操作系统中，普通的桌面应用程序运行在受限的用户态环境中，绝对不允许私自创建或修改底层的网络适配器。

为了打破这一系统特权壁垒，Clash Verge Rev 设计了独立的服务模式（Service Mode）。在安装服务模式时，客户端会通过操作系统的特权提示向系统服务管理器注册一个名为 `clash_verge_service` 的常驻后台服务。该服务拥有高度的系统管理员权限，并在本地回环网络开启受控的命令监听端口。主界面程序只需要向该本地服务发送简洁的控制指令，服务组件便会在后台自动调用底层网络驱动完成虚拟网卡的创建与路由表的修改，从而在确保用户界面轻量化的同时优雅实现特权操作。

### 4. TUN 虚拟网卡模式的进阶路由参数调优

激活 TUN 模式后，网络流量的调度需要兼顾全局穿透与局域网设备互通。

在客户端高级配置中，建议务必保持开启“严格路由”选项。该设置会强制清除宿主操作系统的默认网关残留，杜绝某些拥有双网卡或者启用了 IPv6 的主机在跨国访问时发生未经代理的流量泄漏。与此同时，在私有网段过滤列表中，必须将 `192.168.0.0/16` 等企业内网网段妥善保留，防止在开启全局代理后导致本地网络打印机或公司 NAS 存储无法被发现。

### 5. 专线物理网络对全场景实操的决定性支撑

即便客户端界面的调度机制调优得再完美，如果底层节点线路频繁遭遇公网波动，使用体验依然无法得到保障。

根据梯子云评测实验室的长期全时段实测数据，选用具备成熟运营资质的专业专线服务商（如光速云）能够带来脱胎换骨的改变。由于光速云采用了纯正的企业级 IEPL 内网专线，其节点之间的物理传输不经过公共国际出口，从而在根本上消除了晚高峰丢包与跳 ping 的风险。配合客户端的 Fallback 策略组，双专线热备架构能够实现长达数月不掉线的工业级稳定体验。

### 6. 解决开发工具与在线游戏无法联机的实战方案

许多程序员在日常工作中频繁遭遇 Git 克隆超时、Docker 镜像拉取失败或者海外联机游戏无法登录的困扰。

这些软件普遍存在直接发起裸 TCP 或 UDP 通信的底层特征，完全不理睬浏览器的常规系统代理。解决该问题的终极方案是彻底告别复杂的全局环境变量配置，直接开启客户端的系统服务模式与 TUN 模式。一旦虚拟网卡就位，内核会自动从系统协议栈第三层接管命令行工具与游戏引擎的所有外发网络报文，并将它们无缝送入分流引擎，实现开箱即用的全局网络穿透。


## ⚙️ 底层流量截获与路由调度工程模型

代理客户端之所以能将纷繁复杂的出海流量调度得井井有条，核心在于其在操作系统底层建立了一整套环环相扣的数据包拦截、重构与路由流水线。深入理清这一工程逻辑，能够让排查各种深层网络故障变得轻而易举。

### 1. 操作系统网络协议栈数据包处理全景图

从本地应用程序发起网络调用，到数据包最终穿透物理网络出境，整个生命周期可以通过以下工程图景清晰表达。

```
[ 应用程序发送网络请求 (Socket API) ]
                  │
                  ▼
[ 操作系统网络协议栈 (TCP/IP Stack) ]
                  │
        ┌─────────┴─────────────────────────┐
        │                                   │
        ▼ ( 遵循系统代理的应用 )            ▼ ( 不遵循系统代理的应用 )
[ 本地系统代理端口 ]    [ 操作系统默认网关路由表项 ]
        │                                   │
        │                                   ▼
        │                       [ TUN 虚拟网络适配器 (Wintun) ]
        │                                   │
        └─────────────────┬─────────────────┘
                          ▼
            [ Mihomo 用户态网络协议栈 ]
                          │
            [ 提取目标 IP、端口与 SNI 扩展 ]
                          │
                          ▼
            [ 规则分流决策引擎 (Rule Engine) ]
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
        [ DIRECT ]    [ REJECT ]    [ PROXY (节点集群) ]
```

当应用程序尝试建立网络套接字连接时，如果该程序遵循系统代理规范，流量会直接封装为标准 HTTP CONNECT 或 SOCKS5 请求发往本地监听端口。而对于不遵循系统代理的非标软件，操作系统路由表将其默认网关强行指向 TUN 虚拟适配器。虚拟适配器利用零拷贝环形缓冲区迅速将第三层 IP 数据包送入内核的用户态协议栈。至此，整台电脑所有维度的出站流量均被汇聚在统一的入口管线之中。

### 2. 路由表篡改与 Wintun 驱动的虚拟网络抽象

传统代理工具常采用旧式的 TAP 网卡驱动，由于涉及频繁的用户态与内核态上下文切换，在千兆带宽大吞吐场景下极易导致 CPU 单核占用打满。

现代 Clash 方案在 Windows 平台全面普及了由 WireGuard 团队研发的高性能 Wintun 驱动。Wintun 专门针对第三层 IP 数据包转发进行了极致轻量化设计，舍弃了二层以太网帧的繁琐封装。在激活服务模式时，驱动会在操作系统网络栈中注入一条优先级极高的默认路由表项（Metric 设置为极小值），使其优先于本地物理以太网卡或无线无线网卡生效。这一精巧的设计确保了整机所有应用程序的外发数据包均被平滑截获，且转发延迟控制在微秒以内。

### 3. DNS 劫持防护与 Fake-IP 虚拟地址池映射机制

在传统的网络解析中，操作系统在访问域名之前必须先获取到真实的 IP 地址。而由于境内运营商公共 DNS 普遍存在污染与干扰，直接解析境外域名往往返回错误的受污染地址，导致后续的代理分流彻底失效。

Clash 内嵌的高性能 DNS 服务器通过 Fake-IP 机制完美规避了该技术痛点。当应用程序发起 A 记录查询时，本地虚拟 DNS 会在微秒之内从保留的保留网段（如 `198.18.0.0/16`）中临时划分一个唯一的虚拟 IP 返回给调用方，同时在内存的哈希映射表中建立该虚拟 IP 与真实域名的一对一绑定。当应用程序随后向该虚拟 IP 发起 TCP 握手时，核心直接从内存映射表中快速反查出原始域名，并将原始域名直接封装进代理协议中发往远端境外节点解析，从而在根本上斩断了本地运营商实施 DNS 劫持的一切可能。

### 4. External Controller 控制面架构与长连接通信

图形用户界面与后台转发内核之间采用了完全解耦的松耦合通信架构。

内核在启动后会在本地回环地址开放专用的 RESTful HTTP 与 WebSocket 管理端口。图形客户端（如 Clash Verge Rev）本身并不承担任何繁重的数据包转发工作，它仅仅作为一个优雅的前端控制器，通过定时向 RESTful 接口发送控制指令，或者建立持久的 WebSocket 订阅通道来实时拉取内核的上传下载吞吐量、活动连接列表以及节点健康状态。这种控制面与数据面完全分离的高级架构，确保了即便前端图形界面遭遇卡顿或崩溃，底层的网络代理内核依然能够保持平稳而高效的转发。

对于刚刚接触该代理生态的用户，面对繁琐的参数面板难免感到无从下手。本章精心梳理了从空白环境安装到全平台平稳运行的五个标准化操作步骤，帮助使用者在几分钟内建立起稳固的出海网络环境。

### 第一步 客户端纯净安装与初次启动环境准备

根据操作系统的具体版本，从官方可信源头下载对应的安装包并完成部署。

启动软件后，首先进入客户端的“设置”界面。建议勾选“随系统启动”以及“静默启动”选项，这样电脑每次开机后客户端会自动常驻在右下角系统托盘中，避免每次手动点开的繁琐。同时，检查客户端界面的语言设置，切换为简体中文以便于后续功能的直观辨识。

### 第二步 导入机场订阅链接并完成批量测速

1. 进入左侧的“订阅”功能面板，点击右上角的新建按钮，选择类型为“Online”。
2. 将服务商后台提供的订阅链接完整粘贴至 URL 输入栏中，并为该配置起一个便于区分的名称。
3. 点击保存后，观察订阅卡片下方是否正确显示更新时间与文件大小。
4. 切换至“代理”面板，点击右上角的闪电或测速图标，对所有节点发起批量连通性探测。列表将以鲜艳的颜色标出每个节点的真实往返毫秒数，方便使用者挑选可用线路。

### 第三步 锁定 Rule 规则模式并合理设定出站策略

绝大多数日常场景下，切忌滥用全局模式。

在客户端顶部或者设置菜单中，将代理模式明确固定在“Rule”或“规则”选项上。随后进入代理面板，展开“节点选择”或“PROXY”主策略组。对于追求速度的用户，可以选择将策略指向名称带有“自动选优”或“URL-Test”的子组，让核心自动将流量导向当前响应最快的服务器；对于需要进行店铺运营或特定跨国业务的用户，则应当手动点选一个固定的香港或日本专线节点。

### 第四步 安装服务模式并激活 TUN 全局网卡

为了解决各类桌面游戏客户端、命令行开发工具不走代理的痼疾，必须赋予内核底层网络特权。

在“设置”面板中定位至“服务模式”，点击右侧的齿轮图标唤起安装浮窗。点击“安装”按钮，并在操作系统弹出的 UAC 提权确认框中点击允许。观察服务状态图标由灰色转变为鲜绿色，表明特权网桥已在后台正常常驻。随后返回主菜单将“TUN 模式”总开关拨动至开启状态，此时整台电脑的三层网络流量已被完全纳入代理核心的监管之下。

## 🛡️ 日常使用安全基线与防断网避坑六大铁律

代理软件虽然极大拓宽了访问全球互联网的视野，但若缺乏必要的操作安全规范，日常使用中极易遭遇整机意外断网、账号异地风控甚至局域网凭据泄露等困扰。本章总结了六项必须严格养成的良好使用习惯与防御准则。

### 1. 关机或重启前规范退出客户端，防范注册表代理残留

在新手用户中出现频次最高的技术求助，莫过于“电脑开机后什么网页都打不开，但微信能发消息或者连手机热点也连不上网”。

该故障的根源在于非正常关机导致的系统代理残留。当客户端开启“系统代理”功能时，会在 Windows 注册表网络设置中强行写入一条指向 `127.0.0.1:7890` 的重定向规则。如果你在没有退出客户端的情况下直接点击关机或者合盖断电，下次开机时操作系统依然会将所有网络请求发往该端口。然而此时代理核心尚未启动，导致浏览器向死端口发起连接全部超时。养成在关机前先在系统托盘右键退出客户端的良好习惯，能彻底消灭此类虚假断网故障。

### 2. 严禁长期停留在 Global 全局模式，杜绝账号异地封号

许多用户为了图省事，一旦开启全局模式便数周不再更改，这一危险操作极易引发严重的连带后果。

在全局模式下，包括你的国内网上银行、移动支付、社交账号以及主流电商平台的全部数据请求，都会被强行送往境外出站节点。国内金融与安全风控系统在检测到客户端登录 IP 在几秒钟之内从本土城市瞬间跳跃到海外陌生机房时，会自动判定账号存在被盗用风险，进而触发强制人脸识别或直接实施冻结封号。日常使用务必牢固锁定 Rule 规则模式，让国内流量永远保持纯净的物理直连。

### 3. 公共 Wi-Fi 环境下坚决关闭“允许局域网连接”

在客户端的通用设置中，通常包含一个名为“允许局域网连接”（Allow LAN）的开关选项。

该功能原本是用于让同一 Wi-Fi 下的手机或平板通过电脑共享代理网络的。然而在机场、咖啡厅或酒店等公共开放网络环境下，开启此项功能等同于将你的电脑代理端口对同一热点下的所有未知陌生设备完全敞开。黑客不仅可以借用你的代理通道发送恶意数据，甚至可以通过扫描该开放端口探测你的本地网络通信。在离开家庭或私有办公网络时，必须确保此开关处于关闭状态。

### 4. 面对订阅更新失败，切忌盲目乱点破坏正常配置

当服务商的订阅服务器遭遇维护或者短时网络波动时，客户端可能会弹出红色背景的更新失败提示。

许多缺乏经验的用户在此类情况下极易陷入恐慌，开始在设置中盲目重置系统网络、卸载重装客户端甚至清空全部配置。实际上，Clash 内核具备完善的本地离线缓存保护。只要本地现有的节点列表依然能够正常连接，订阅更新失败仅仅代表暂时无法同步最新的服务器列表，对当前进行的跨国工作完全没有任何负面干扰。此时最明智的策略是静待几小时后再次尝试，绝不可随意破坏已正常工作的本地配置。

### 5. 警惕以开机自启为幌子的恶意系统常驻项

在开启客户端的开机自启动功能时，务必核对注册表启动项的合法路径。

某些从非正规下载站获取的恶意二次打包客户端，在所谓的随系统启动脚本中绑定了恶意的静默命令行，在每次开机时先于代理核心在后台拉起隐蔽的远程木马程序。用户可以在 Windows 任务管理器的“启动应用”列表中，右键查看 Clash 程序的物理文件属性，确保其路径精准指向正规的应用安装目录，且数字签名无任何异常篡改。

### 6. 认准成熟运营年限的合规专线服务，拒绝低价年付陷阱

再精妙的客户端操作技巧，也无法拯救一个随时准备跑路的劣质机场。

网络黑产圈中充斥着大量以极低价格为诱饵的新型快餐服务商。这些站点通常租用廉价的公网服务器拼凑节点，甚至以超低的年付资费诱导新手买单，在收取足额资金后突然拔线失联。使用者不仅面临资金损失，更会导致日常重要的研发与跨境业务瞬间瘫痪。在选择节点支撑时，必须优先考察服务商的真实持续运营时间与物理专线冗余，将核心生产力建立在坚不可摧的基础之上。


## 💬 常见长尾技术问题深度解答

为了让新手用户在遭遇网络异常时具备快速排错的能力，本章汇总了在使用各类 Clash 客户端过程中最常见的十个典型疑问并给出权威技术解答。

### Q1 为什么有时候电脑开机后连百度都打不开，必须先打开代理才能上网？

这是由于上一次关机时未正常退出代理客户端，导致操作系统底层的系统代理开关发生残留。在客户端开启系统代理时，Windows 注册表会自动将网络出站定向到本地的专用端口。若在未关闭代理前强行关机，下次开机时由于客户端并未启动，浏览器向该本地端口发送数据全部无应答。解决该问题只需重新启动代理客户端并正常退出，或者进入 Windows 系统的“设置” ➔ “网络和 Internet” ➔ “代理”，将“使用代理服务器”手动拨动为关闭状态即可瞬间恢复。

### Q2 规则模式和全局模式在日常看视频与办公时究竟该怎么选择？

绝大多数日常场景必须坚定不移地选用 Rule 规则模式。在规则模式下，分流引擎会自动识别目标网站归属地，国内访问自动走本地高速通道，只有境外受阻网站才走加密代理节点。全局模式则会不加区分地将所有流量无论境内境外全部送往海外，这不仅会导致国内网页打开缓慢、耗尽机场昂贵的流量配额，更可能触发国内网银或社交软件的异地登录冻结风控。全局模式仅建议在怀疑特定冷门海外网站未被现有规则覆盖时用于临时验证。

### Q3 开启了系统代理，但为什么在终端中使用 Git 或 npm 依然频繁报错超时？

这是由于命令行终端工具与通用网页浏览器在网络通信机制上存在本质差异。网页浏览器会自动遵循操作系统的全局代理环境变量，而 Git、npm、pip 以及 Docker 等专业开发工具默认直接调用底层的操作系统网络套接字，完全无视系统的代理设置。彻底解决这一痛点的方案是在客户端中安装系统服务模式并开启 TUN 虚拟网卡模式，利用三层虚拟适配器直接从网卡层接管终端外发的全部数据包，无需再手动配置繁琐的终端环境变量。

### Q4 为什么某些国内软件在开启代理后提示区域版权限制或网络错误？

该故障通常是因为这些国内应用程序的通信域名未被正确识别为直连，或者你的分流模式被误选为了 Global 全局模式。当这些受版权保护的国内流媒体平台检测到你的出站 IP 属于境外机房时，会自动判定为跨区访问并弹出版权封锁拦截。应对策略是首先检查当前是否处于 Rule 规则模式，随后进入软件的“连接”面板，观察该应用发起请求时命中哪条规则，必要时通过扩展配置将该应用域名手动追加进 DIRECT 直连白名单即可完美解决。

### Q5 在代理面板中点击批量测速，显示的毫秒延迟数值究竟代表什么？

界面上的节点测速延迟，通常是通过向特定的远端公共端点发送极小的 HTTP 握手请求测算出的单次往返耗时。该数值仅代表本地电脑到达该代理服务器物理链路的握手反应敏捷度，完全不等于长周期大带宽持续传输的上限。一个测速仅有数十毫秒的节点，如果处于高峰超卖状态，在实际下载大文件时依然可能发生严重丢包。在选购和评价节点品质时，应当重点考量晚高峰极端网络环境下的真实吞吐带宽与丢包率。

### Q6 如何在局域网内共享当前电脑的代理，让手机或智能电视顺畅上网？

在客户端主界面的通用设置中，找到并开启“允许局域网连接”（Allow LAN）开关。随后打开系统的命令行窗口，输入 `ipconfig` 查看当前电脑在局域网内的真实 IPv4 地址（例如 192.168.1.100）。接着在手机或电视盒子的 Wi-Fi 高级设置中，将代理类型修改为“手动”，代理服务器主机名填入该电脑 IP 地址，端口填入客户端默认的混合端口（通常为 7890）。只要确保电脑不进入深度休眠，局域网设备即可无缝共享出海网络。

### Q7 安装服务模式时，Windows 系统弹出错误或指示灯一直显示灰色怎么办？

服务模式安装失败通常是由本地安全杀毒软件的特权拦截或者旧版本残留服务冲突导致的。首先应当确保你使用的是操作系统的 Administrator 本地管理员账户，并在安装前暂时退出具有强行拦截驱动安装功能的第三方安全卫士。如果问题依旧，可以按下快捷键 Win 加 R 输入 `services.msc` 打开系统服务管理器，在列表中寻找名为 `clash_verge_service` 的旧服务项手动删除。重启电脑后再在客户端中点击安装通常能够顺畅通过。

### Q8 开启 TUN 模式后，局域网内的打印机或群晖 NAS 为什么突然无法访问了？

这是由于 TUN 虚拟网卡的高级路由策略强行接管了原本属于本地私有局域网的数据报文。要恢复局域网设备的顺畅通信，需要在客户端的 TUN 高级配置中，将 `192.168.0.0/16`、`10.0.0.0/8` 以及 `172.16.0.0/12` 等私有保留网段严格加入绕过列表（route-exclude-address-set）中。同时在主规则列表顶部手动加入针对局域网 IP 的 DIRECT 直连指令，这样发往内网共享设备的数据就会直接通过本地物理路由器通信而不被虚拟网卡拦截。

### Q9 代理软件长期在后台运行，会产生大量日志导致固态硬盘损耗吗？

在默认的正常运行模式下绝对不会。正规客户端在发布时默认将日志输出级别设定为 Info 或 Warning，仅在内核发生严重的连接中断或崩溃时才向磁盘写入极微小的错误片段，日常运行时的绝大部分网络转发全都在内存中完成，对硬盘的读写磨损完全可以忽略不计。但需要注意切勿在生产环境中长期开启 Debug 深度排错级别，因为 Debug 模式会记录每一个数据包的详细报文头，不仅白白耗费磁盘存储，更存在个人隐私外泄的潜在隐患。

### Q10 为什么某些境外网站在电脑上打不开，但切换到手机上却能正常访问？

这种平台差异通常源于电脑浏览器与手机端不同的 DNS 缓存以及扩展插件的干扰。首先电脑浏览器的本地 DNS 缓存可能在开启代理前已经记住了被污染的错误 IP，此时可在浏览器地址栏清除内部 DNS 缓存或者重启浏览器。其次是某些电脑浏览器安装了具备代理控制权的第三方翻译或广告屏蔽扩展，这些扩展可能会覆盖系统的全局代理规则。最后应核对电脑客户端的规则库更新时间，确保分流规则集与手机端保持同步更新。
