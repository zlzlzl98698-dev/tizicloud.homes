### 1. Rule 规则分流与 Global 全局出站的流量路由机理

理解规则模式与全局模式的分歧，关键在于理清网络数据包在进入代理核心后的裁决逻辑。

在 Rule 规则模式下，数据包到达分流引擎后，核心会调出路由表自顶向下逐行比对。例如当你在浏览器中打开国内主流视频站点或电商应用时，其域名与目标 IP 会准确命中预设的 GEOIP 或 DIRECT 直连条目，核心直接调用本地物理网卡将数据发往本土互联网，丝毫不占用任何境外代理流量。只有当访问被墙的海外社交平台或学术数据库时，流量才会匹配到 PROXY 规则并封装发往出海专线。

而在 Global 全局模式下，内部的整个智能分流决策引擎会被强制彻底绕过。无论你的请求目标是国内银行、本地局域网路由器还是海外网站，核心都会不加辨别地将每一个数据包全部塞进当前选定的出站节点隧道中。这不仅导致原本秒开的国内应用因为绕行海外而变得奇慢无比，更会导致国内金融风控系统将你的账户标记为异常异地登录。因此，全局模式仅应作为调试分流规则失效时的临时排障工具。

### 2. System Proxy 环境变量与 TUN 虚拟网卡的深层差异

许多用户困惑为什么勾选了客户端界面上的系统代理开关后，命令行中的 Git 克隆或者大型在线游戏依然无法连接境外网络。

系统代理的本质是在 Windows 注册表或 macOS 系统配置中声明了全局 HTTP 与 SOCKS 代理的环境变量。这个机制是软性的，完全依赖上层应用程序自觉读取并遵守系统代理配置。像 Chrome、Edge 等通用浏览器天生会主动读取该设置，因此可以开箱即用顺畅翻墙。然而，大多数专业开发工具、游戏引擎以及防作弊模块在设计之初就直接调用底层的网络套接字接口，完全不理睬操作系统的代理环境变量。

TUN 虚拟网卡模式则在操作系统内核与物理网卡之间插入了一张虚拟的网络适配器驱动。它通过修改系统默认路由表，将整台电脑的所有 IP 数据报文在网络层第三层强行截获并重定向至代理核心。在 TUN 模式下，无论应用程序是否支持代理设置，哪怕是直接发起裸 UDP 广播的联机游戏，所有网络流量都无法逃逸核心的精准监管，真正实现了操作系统级别的全透明全局接管。
