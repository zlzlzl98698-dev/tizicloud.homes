## 🛠️ 从安全获取到无毒运行的五步标准作业规范

为了确保每一位用户在部署 Clash Verge Rev 的全流程中杜绝任何安全隐患，本章制定了严格的标准作业程序。遵循该规范能够将安装包中毒、驱动加载失败以及网络瘫痪等常见故障消灭在初始阶段。

```
[ 第一步：官方仓库溯源 ] ──▶ [ 第二步：架构精确选型 ] ──▶ [ 第三步：本地哈希核验 ]
                                                                      │
[ 第五步：连通性与服务巡检 ] ◀── [ 第四步：系统放行与安装 ] ◀─────────┘
```

### 第一步 官方仓库权威溯源与假冒网站识别

安全获取的首要铁律是永远不要通过通用搜索引擎的常规关键词检索随意点击首屏带有推广字样的网页链接。

正确的途径是直接定位至 GitHub 上的 Clash Verge Rev 官方开源仓库。在访问页面时，核对其组织名称与代码提交历史，确认其星标数量、贡献者团队以及近期的更新动态。切勿在任何声称无需翻墙一键下载的个人网盘或私人博客下载被二次封装的文件。

### 第二步 依据系统与处理器架构下载专属资产

进入 Release 版本发布页面后，展开 Assets 资源下拉列表。

此时应当根据此前决策表分析出的硬件平台，找到唯一对应的文件名。例如 Intel/AMD 芯片的 Windows 10/11 用户直接下载以 `_x64-setup.exe` 结尾的安装文件；Apple Silicon 芯片的 Mac 用户直接下载以 `_aarch64.dmg` 结尾的文件。同时，将同版本发布页面下方的校验文本文件或表格一并复制保存至本地，用于接下来的哈希比对。

### 第三步 执行终端密码学 SHA256 散列值核验

将下载完成的文件保存在本地固态硬盘目录中，打开系统命令行工具。

严格执行本指南前文提供的哈希计算指令，获取本地文件的六十四位散列字符串。将该散列串与官方公布的指纹列表逐字比对。如果发现任何一个字符存在差异，表明本地安装包在传输过程中遭受了恶意篡改、网络截获或者文件严重损坏，此时必须立即将其彻底粉碎删除，绝不可强行执行。

### 第四步 系统特权放行与标准安装部署

在确认哈希完全一致的前提下，启动安装程序。

在 Windows 环境中，如果系统弹出用户账户控制（UAC）提权确认框，确认发布者信息后点击允许继续。安装向导将全自动部署图形界面组件与本地后台服务。在 macOS 环境中，将应用图标拖入 Applications 应用程序文件夹后，如遇开发者未知警告，按照前文指导在系统设置中放行或通过终端命令剥离隔离属性，即可顺利完成桌面常驻。

### 第五步 核心网络服务与健康状态自检

首次启动客户端后，先不要急于载入庞大的外部订阅，应先对基础核心组件展开三项健康体检。

<div class="tz-table-wrap">

| 自检检查项 | 检查路径与操作动作 | 正常预期状态 | 异常处理指引 |
| :--- | :--- | :--- | :--- |
| **内核版本识别** | 进入软件左下角“设置” ➔ “关于” | 显示最新的 Mihomo 稳定版或 Alpha 版标识 | 若显示内核丢失，进入设置点击重新下载并解压内核 |
| **服务模式运行状态**| 进入“设置” ➔ 观察“服务模式”指示灯 | 指示灯呈现鲜明绿色，显示服务已就绪 | 点击右侧齿轮尝试重新安装，检查杀毒软件是否拦截 |
| **本地控制器通信** | 观察右上方网络延迟与吞吐监控仪表盘 | 能够正常轮询展示实时网络带宽与内存占用 | 检查 External Controller 默认监听端口是否被其他软件占用 |

</div>

只要上述五步检查无误，当前系统的网络代理工作环境即告完全稳固建立，后续即可安全导入节点订阅并享受极速跨境网络。
