## 🛠️ Clash Verge Rev 五步落地实操路线图

为确保网络代理环境兼具卓越速度与极高可靠性，从软件下载到最终的流量调度需要遵循系统化的实施流程。本指南提炼出从环境准备到防泄漏核验的标准五步作业规范，帮助使用者快速完成无缝迁移。

```
[ 第一步：架构匹配与安装 ] ──▶ [ 第二步：内核选用与升级 ] ──▶ [ 第三步：服务模式与 TUN 激活 ]
                                                                             │
[ 第五步：全链路泄漏核验 ] ◀── [ 第四步：订阅导入与规则注入 ] ◀──────────────┘
```

### 第一步 操作系统架构识别与正确安装包选型

用户在部署 Clash Verge Rev 时，首要前提是根据硬件架构选择适配的二进制安装介质，防止因系统转译层导致内存损耗或崩溃。

- **Windows 平台**，绝大多数 Intel 或 AMD 64 位台式机与笔记本应选择 `x64-setup.exe` 安装包。若使用高通骁龙芯片的新一代 Windows on ARM 设备，必须选择 `arm64-setup.exe` 原生包，避免跨架构仿真带来的性能开销。
- **macOS 平台**，M1、M2、M3 及 M4 系列芯片的苹果电脑，请务必下载文件名带有 `aarch64.dmg` 的安装镜像。若是早期的 Intel 处理器机型，则选择 `x64.dmg`。首次启动若弹出未签名安全提示，需在系统设置的隐私与安全性中点击仍要打开。
- **Linux 平台**，主流发行版首选经过沙箱环境验证的 `AppImage` 镜像或者 Debian/Ubuntu 专用的 `deb` 软件包，在终端赋予执行权限后即可启动。

### 第二步 选用 Mihomo 核心与 Alpha 实验通道配置

Clash Verge Rev 自带标准稳定版内核与 Alpha 测试版内核双轨道机制。对于追求最新协议支持的用户，合理配置内核版本至关重要。

在软件左侧菜单进入“设置”，找到“Clash 内核”选项。默认情况下，客户端搭载经过严苛回归测试的稳定版 Mihomo 核心。若使用者的机场节点已开始采用最新的 VLESS 组合协议或者新型多路复用方案，建议点击切换至 Mihomo Alpha 内核。切换过程仅需两秒即可热加载完成，无需重新启动整个客户端应用。

### 第三步 安装系统服务模式并激活 TUN 虚拟网卡

接管无代理配置支持的应用软件流量，必须通过服务模式赋予客户端内核底层的虚拟网卡配置权限。

1. 保持操作系统处于管理员账号环境，在客户端“设置”页面找到“服务模式”（Service Mode）。
2. 点击右侧齿轮图标进入管理浮窗，点击“安装”按钮。Windows 系统会弹出 UAC 提权确认框，点击允许后服务即可常驻后台。
3. 观察服务模式状态图标由灰色转为鲜绿色，表明 Windows Service 或 macOS LaunchDaemon 守护组件已正确就绪。
4. 返回主设置菜单，将“TUN 模式”开关拨动至开启状态。系统网络适配器列表中将立即新增名为 `Meta` 或 `wintun` 的高性能虚拟接口，实现操作系统三层网络的全包拦截。

### 第四步 导入订阅链接与 Script 扩展规则注入

节点订阅的有效管理与自动化预处理是保证日常流畅体验的关键。

在“订阅”管理界面，点击右上角新建配置，选择类型为“Online”，将服务商提供的订阅链接完整粘贴至 URL 输入框，并设置合理的自动更新间隔，建议设定为 24 小时以获取最新的服务器拓扑变更。

若需要针对特定企业域名、学术数据库或内网网段实施分流覆盖，无需手动修改庞大的原始 YAML。直接在该订阅条目上点击鼠标右键，选择“编辑扩展配置”，利用 JavaScript 脚本管道在运行时动态插入自定义规则组，实现配置与上游更新的彻底解耦。

### 第五步 跨境链路连通性与 DNS 防泄漏终审测试

完成所有代理与分流设置后，切忌盲目依赖单一测试网页，必须执行标准的三层验证流程。

<div class="tz-table-wrap">

| 验证层级 | 推荐验证工具与端点 | 正常表现判定标准 | 异常排查方向 |
| :--- | :--- | :--- | :--- |
| **基础穿透层** | 访问国际公共 IP 探针站点 | 返回的出口 IP 归属地与当前选定的策略组节点完全一致 | 检查系统代理开关是否开启，排查本地安全软件防火墙拦截 |
| **DNS 泄漏层** | 使用 DNSLeakTest 扩展测试 | 仅出现出站代理服务器所在地的递归解析节点，无境内运营商 DNS | 检查 TUN 设置中的 DNS 劫持开关，强制开启 Fake-IP 模式 |
| **WebRTC 层** | 浏览器 WebRTC IP 检测页面 | 本地内网真实公网 IP 完全被掩蔽，不暴露真实接入地址 | 在浏览器扩展或配置中关闭非代理接口的 WebRTC 候选者广播 |
| **休眠恢复层** | 笔记本盒盖休眠三分钟后唤醒 | 唤醒后十秒内网络连接迅速自愈，无需手动开关代理 | 确认 Service Mode 守护进程状态正常，检查系统电源事件日志 |

经过以上五个步骤的层层递进，系统便建立起一套兼顾极致性能、严格隔离与抗干扰能力的现代化网络代理运行环境。
