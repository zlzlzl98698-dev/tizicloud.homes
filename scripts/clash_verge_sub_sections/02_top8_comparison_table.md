### 1. Script 动态处理与 Merge 静态覆盖的执行流水线

在处理庞大且复杂的节点订阅时，理解客户端内部的配置预处理顺序对于精确控制路由行为至关重要。

客户端在从远端接口拉取到原始 YAML 文本后，首先进入语法有效性验证阶段，随后将其转换为内存中的 JavaScript 对象数据结构。若用户启用了 Script 扩展，该对象会作为参数完整传入用户编写的 `main(params)` 函数中。用户可以通过代码遍历 `params.proxies` 节点数组，剔除倍率过高的冷门节点，或者利用正则表达式将属于特定国家地区的服务器动态提取至专用的出站策略组中。

在脚本执行完成后，系统接着应用 Merge 规则。Merge 模块会将用户预先写好的直连白名单或代理域名列表以静态追加的方式与现有规则表合并。这种双重管道设计既赋予了专业人员强大的动态清洗能力，又让普通用户能够通过直观的 YAML 块快速添加自定义规则，两者互不冲突且各司其职。

### 2. URL-Test 自动测速与 Fallback 主备容灾的心跳探测原理

在多节点甚至多机场环境下，如何让流量始终保持在最优路径上，核心在于动态策略组的探测算法设计。

URL-Test 策略组会在后台按照用户预设的探测周期（例如每三百分钟或六十分钟），向一个高可用且低开销的全球公共端点（如 Google 生成空白返回的测速接口）并发发送轻量级 HTTP HEAD 请求。核心根据各节点的真实往返握手耗时动态建立有序队列，将所有出站流量自动导向当前延迟最低的节点。该机制极其适合对峰值速度敏感的大流量流媒体播放与文件下载。

而 Fallback 故障转移策略组则遵循严格的保活优先级原则。它并不会单纯因为某个备用节点延迟较低而频繁切换，而是始终将首选节点作为主力出口。只有当主力节点在设定的心跳周期内连续多次探测超时或者出现严重丢包时，核心才会触发平滑熔断，将后续建立的新套接字无缝转移至备用专线。一旦主力专线恢复健康心跳，流量又会自动回切至主力路径。这种稳定性优先的调度模型是跨国办公与远程运维的理想选择。
