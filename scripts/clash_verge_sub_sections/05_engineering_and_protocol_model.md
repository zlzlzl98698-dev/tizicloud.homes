## ⚙️ 订阅数据管道与运行时规则解析流水线

在复杂的规则路由体系中，订阅配置的解析质量与策略拓扑的计算效率直接决定了系统的并发转发能力。本章深入剖析配置文件反序列化流水线、Rule-Providers 远程规则集动态拉取机理、策略组有向无环图拓扑排序，以及多维主动健康探针的运作模型。

### 1. 订阅配置的反序列化流水线与类型安全保障

大型机场订阅往往包含数以千计的代理服务器定义与错综复杂的分流规则，如果解析引擎性能低下，极易引发图形界面的瞬间卡死甚至内存溢出。

```
[ 原始订阅网络数据流 ]
          │
          ▼
[ Rust 原生内存解码与反序列化 (Serde) ]
          │
          ▼
[ 抽象语法树校验与字段格式清洗 ]
          │
    ┌─────┴───────────────────────────────────┐
    │                                         │
    ▼                                         ▼
[ 节点集群数组 Proxies ]                  [ 规则提供者 Rule-Providers ]
    │                                         │
    ▼                                         ▼
[ 策略组有向无环图 (DAG) 拓扑排序 ]       [ 异步拉取与本地二进制缓存 ]
    │                                         │
    └─────────────────┬───────────────────────┘
                      ▼
            [ 运行时规则路由表编译就绪 ]
```

Clash Verge Rev 借助 Tauri 架构的底层优势，调用由 Rust 编写的高性能 Serde 解析引擎在原生工作线程中完成数据解构。解析器在读取 YAML 文本时首先实施严格的静态类型校验，对于缺失必要加密参数或端口范围异常的非标节点执行静默剔除，避免非法数据污染后续的路由决策树。完成反序列化后的纯净数据结构随后通过高速内存管道直接映射至代理内核，实现百万字节配置的毫秒级即时载入。

### 2. 策略组有向无环图（DAG）拓扑排序与死锁检测

在进阶用户的配置文件中，策略组之间常常存在深度的嵌套与引用关系。例如一个名为“全球流媒体”的策略组可能引用了“自动选优”组，而“自动选优”组内部又包含了多个按地区划分的二级策略组。

为了确保流量在分流决策时能够按照正确的顺序层层穿透，内核在加载配置时会将所有的策略组建模为一个有向图。内核调度引擎通过执行深度优先搜索算法对整个关系网进行拓扑排序，并在图计算过程中实时检测是否存在环形引用死锁。一旦检测到组间循环引用的致命配置错误，内核会立即触发容错机制打断循环依赖关系，将受影响的策略组强制降级指向默认的 DIRECT 直连或全局出站，彻底避免系统陷入无限递归引发程序崩溃。

### 3. Rule-Providers 动态规则集异步拉取与增量合并

现代代理规则已经从单调的静态规则列表演进为模块化的远程规则提供者（Rule-Providers）体系。

当配置文件中声明了指向外部开源规则库的 URL 时，Mihomo 核心会在后台启动异步非阻塞的网络工作池并行拉取规则包。为了最大程度节约本地带宽与计算开销，核心支持基于 HTTP ETag 与 Last-Modified 头部实施增量更新检查。若远端规则库未发生变更，核心直接读取保存在本地磁盘上的预编译二进制规则缓存；若有新规则释出，解析器在后台线程完成重构后平滑热替换当前规则树，整个过程对当前进行中的网络长连接完全零中断。

### 4. 节点健康状态探针与多维主动心跳协议

策略组能否在遭遇突发断流时做出毫秒级的准确切换，取决于健康探针的探测机制是否科学。

内核针对代理节点提供了多层次的主动健康监测手段。探针并不单纯依赖容易被机房防火墙静默丢弃的 ICMP 协议，而是优先采用模拟真实业务流量的 HTTP HEAD 或 TCP 握手探针。

探针会定期向目标测试服务器发起微小的数据包往返请求，精确测算从发起连接、TLS 握手完成到接收到首字节（TTFB）的完整时延。同时，核心具备智能的抖动滤波算法，连续多次成功才会被判定为可用，而在连续两次丢包后即可果断触发熔断。这种灵活性使得策略组在面对复杂的跨境网络波动时，始终能够做出理性而稳健的出站选择。
